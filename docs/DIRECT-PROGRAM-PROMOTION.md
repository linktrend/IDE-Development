# Direct Program promotion

Program delivery integrates one independently reviewed exact Phase candidate into Development through normal protection. Main promotion opens a temporary `promote/main/<development SHA prefix>` PR and reuses the matching successful Full receipt and protected Development transition identity. It never reruns Full. The designated Program lead prepares this PR; the Principal explicitly approves its exact source, prior main target, candidate head and receipt before normal protected merge.

The retained `promote-staging` controller and shell entrypoints fail before any mutation. Source Policy rejects staging PR targets. Existing staging refs, rulesets, history and open PR targets remain preserved; this source update does not authorize deletion or protection changes.

The Main controller rechecks live Development/main tips at packaging and after approval, same-repository open non-draft PR, expected temporary branch/head and exact marker. Wrong or changed receipt identities remain rejected. Known worker and unknown roles fail closed; promotion requires `program-lead` or `founder`. The retained shell package route uses `LINKTREND_CONTROLLER_ROLE=program-lead`; it cannot complete a Main merge. These role declarations record the operational exclusive-writer lease; they do not cryptographically distinguish agents sharing one GitHub identity. GitHub protection and explicit Principal approval remain independent authority boundaries.

CLI `prepare-main` promotion input uses `developmentSha`, `mainSha`, and `candidateSha`. `promote_main.sh` supports package preparation and read-only reevaluation. It packages the exact Development source and validates its existing receipt and transition before publishing only the temporary promotion ref and PR. Legacy `MODE=approve-merge` fails at entry before tools or credentials. All actual Main merges use `delivery_controller.py complete-main` with the explicit Principal approval JSON bound to source, prior Main, promotion head, and receipt, as described in `docs/contracts/LISA-MAIN-APPROVE-DISPATCH.md`. No admin merge or protected direct push is added. The main receipt workflow checks the marker against live Development and the promotion head using trusted default-branch code only.

This is common-source implementation only. Each repository needs an independently reviewed exact baseline/allowlist installation packet that preserves newer consumer controllers and unrelated managed drift. A source checkpoint is not an installed consumer policy, a hosted PASS, a release admission, a deployment, or a grant. Existing per-repository cost and protected-operation windows still apply.

The package pairs its `review.bugbot=disabled` config with the published minimal parser/schema migration. Legacy `final-candidate-only` input normalizes to disabled and cannot enable a request. The schema preserves all six exact receipt identity fields, including `headCommit`. No native review adapter or extra spending dependency is introduced.
